# 6.4.3 自治策略层最小可用方案（贾维斯基座）

> 负责人：进化规划师｜日期：2026-11-10｜时区：Asia/Shanghai
> 来源：贾维斯架构蓝图 v1 第 5 节路线 6.4.3「自治策略层 skill：自主 vs 请示的判断 + 决策日志」+ 第 2 节架构 L5 策略/自治层（缺口）。
> 性质：阶段 6 贾维斯基座第 3 步；与 A 线 1.2 闸门解耦，本线只写 `dsh-bot-evolution/`。
> 红线：零外部账号、零凭据明文、最小权限；**安全侧默认——凡未明确落入「自主」清单的动作，一律「先请示」**。

## 0. 目标与边界

- **目标**：让副驾具备贾维斯特质 #7「主动提醒/预判」所需的决策内核——接到任务先判定「自主干 vs 请示」，并落结构化决策日志，可复核、可回滚、可审计。
- **本步范围**：沉淀判定框架 + 决策日志格式 + 一个可运行的 PoC 判定器（`autonomy-policy-poc.py`）+ 封装共享 capability `autonomy-policy`，挂执行 bot。
- **不做的**：不自动执行高危动作（执行权仍在各 capability 与用户授权内）；不做意图路由/任务规划的完整 planner（蓝图 L5 的 planner 留待后续）；不碰 `assistants/`、`ego/`、`state.json`。

## 1. 设计依据

- 蓝图第 6 节验收项：「自治策略：给定任务能自判『自主 / 请示』并留决策日志」。
- 蓝图第 7 节风险边界：「自治策略层上线前，凡涉及用户授权/外部账号/凭据的动作一律先请示」。
- 6.4.2 方案第 4 节接入点：「语音指令走与文字相同的自治策略层（6.4.3 待做）与硬闸门；涉及授权/外部账号/凭据的动作一律先请示，不因『听到』就自动执行高危操作」——本步即补这个接入点。
- 现有红线（ROADMAP 第 2 节反模式 1/2/9、阶段 6 边界）：1.2 未过期间不碰 `assistants/`；零凭据明文；最小权限。

## 2. 判定框架（决策矩阵）

**默认安全侧**：先扫「请示规则」，命中任一即 `ASK`；再扫「自主规则」，命中即 `AUTONOMY`；两者都不中 → 默认 `ASK`。

### 2.1 请示规则（高优先，命中即停）

| 类别 | 命中模式（关键词/标签） | 原因 |
| --- | --- | --- |
| 外部身份 | 外部账号、登录、注册、开通 | 涉及外部账号/身份 |
| 凭据 | 凭据、token、密码、密钥、secret、api key、pat | 涉及凭据/密钥 |
| 金钱 | 支付、付款、购买、订阅、付费、转账、充值 | 涉及金钱支付 |
| 不可逆 | 删除、清空、格式化、rm、del、drop、永久移除 | 不可逆删除 |
| 强结束 | 强关、强制关闭、kill、结束进程、终止进程 | 强制结束进程/窗口 |
| 对外发送 | 发邮件、发消息、外发、推送、发布、上传、提交 github、发帖 | 对外发送/发布 |
| 越界写 | 改 assistants、改 ego、改 state.json、写用户画像 | 闸门未过期间受保护目录 |

## 3. 决策协议（流程）

```
接到任务
  → 解析动作类型（提取任务文本）
  → 对照矩阵（先 ASK 后 AUTO，否则默认 ASK）
  → 输出判定：AUTONOMY / ASK + 触发规则 + 原因
  → 若 AUTONOMY：在已验证能力范围内执行，落决策日志
  → 若 ASK：停下，向用户呈报任务+判定，等明确点头才执行
  → 每条决策写入 autonomy-decision-log.md（时间戳/Bot/判定/原因/规则/任务/用户确认）
```

## 4. 决策日志格式（结构化落盘）

文件：`dsh-bot-evolution/autonomy-decision-log.md`（UTF-8，追加写，首行建表头）。

```
| 时间 | Bot | 判定 | 触发原因 | 规则 | 任务 | 用户确认 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-11-10 08:00:00 | 进化规划师 | AUTONOMY | 本机只读-桌面感知 | AUTO:截屏 | 截个屏看看 | None |
| 2026-11-10 08:01:00 | 进化规划师 | ASK | 涉及凭据/密钥 | ASK:token | 把 token 填进配置 | pending |
```

## 5. 封装为共享 capability `autonomy-policy`

- 五段结构（目标 / 前置 / 步骤 / 常见坑 / 验收）+ 安全规则，注册进共享能力目录。
- 接入点：所有文字/语音入口在「执行前」先调本 capability 判定；`voice-io` 的语音指令同样走这套判定，不绕过。
- 执行 bot 挂 `autonomy-policy` 后，任何任务先自判 + 留日志，再决定是否动手。

## 8. 风险与边界

- **安全侧默认**：宁可多问，不可擅动；未明确自主的一律请示。
- **不绕过闸门**：1.2 未过期间，任何写 `assistants/`/`ego/`/`state.json` 的动作归 ASK，不因「自治」越界。
- **语音不例外**：voice-io 听到的指令同样走本判定，不因「听到」就执行高危。
- **Bot 失联降级**：若判定器所在 Bot AUTH 失联，admin 代判并标注「X Bot 失联，admin 代判」，不谎称原主责已完成。
- **零越闸**：本线只写 `dsh-bot-evolution/`，不碰受保护目录；凭据经 `request_secret`，不写明文。
